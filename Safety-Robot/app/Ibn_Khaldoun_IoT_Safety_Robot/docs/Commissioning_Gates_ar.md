# بوابات الاعتماد قبل أي ربط ميداني

لا توجد بوابة برمجية واحدة تجعل الروبوت صالحًا لمنشأة خطرة. يتطلب الانتقال من المحاكاة إلى أي نظام ميداني برنامج اعتماد متعدد التخصصات وقرارًا صريحًا من مالك المنشأة والجهات الهندسية المخولة.

| البوابة | دليل القبول المطلوب | حالة هذه الحزمة |
|---|---|---|
| تحليل المخاطر | HAZOP/FMEA، مخططات أسباب ونتائج، تعريف مستويات الحماية وحدود التشغيل. | غير منفذ؛ خارج نطاق البرمجيات. |
| الحساسات | اختيار معتمد للبيئة، معايرة، انحراف، زمن استجابة، تشخيص انقطاع/قصر، وسجل شهادات. | غير منفذ. |
| الصمام والمشغلات | نظام مستقل fail-safe، اختبار وضع الطاقة/الفشل، interlocks مادية، وقرار مسؤول مخول. | محظور برمجيًا. |
| الملاحة | تحليل منطقة، geofencing، إيقاف طوارئ مادي، اختبارات عوائق وسرعة وممرات مصرح بها. | محظور؛ لا توجد ملاحة ميدانية. |
| الاتصالات | شبكات معزولة، هوية أجهزة، تشفير، تدوير مفاتيح، threat model واختبار انقطاع WiFi/GSM. | محاكاة بلا اتصال خارجي. |
| الاستجابة | runbooks، تمارين، تسلسل إشعار معتمد، opt-out للرسائل غير الطارئة، وملكية القرار. | لا توجد إشعارات خارجية. |
| التشغيل التجريبي | HIL/SIL، اختبار قبول موقعي، تدريب مشغلين، مراقبة، rollback وkill-switch مستقل. | مطلوب مستقبلًا. |

> لا ينبغي أن تكون بيانات GPS أو قراءة sensor منفردة أو نموذج تصنيف سببًا وحيدًا للتحكم في الوقود أو الإخلاء أو إعلان حالة طوارئ. القرار الفعلي يحتاج طبقات حماية مستقلة وإجراءات المنشأة المعتمدة.
